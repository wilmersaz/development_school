📚 Historia de las APIs Web

La evolución de las comunicaciones web a través del tiempo

🌐 El inicio de todo

¿Qué es una API Web?

Una API Web (Application Programming Interface) es un conjunto de protocolos y herramientas que permite que diferentes aplicaciones se comuniquen entre sí a través de internet.

💡 Analogía simple:

Es como un camarero en un restaurante: toma tu pedido (request), lo lleva a la cocina (servidor), y te trae la comida (response).

🔄 Flujo básico de una API

1 Cliente hace petición
2 Servidor procesa petición
3 Servidor envía respuesta
4 Cliente procesa datos

⏳ Línea de tiempo de las APIs Web

1990s - Los inicios 🌱

Common Gateway Interface (CGI)

Los primeros scripts para hacer páginas web dinámicas

Características:
  • • Scripts en Perl, C, Python
  • • Cada petición crea un nuevo proceso
  • • Muy lento y limitado

HTTP/1.0 (1996)

El protocolo que permitió las comunicaciones web

Limitaciones:
  • • Una conexión por petición
  • • Sin cookies o sesiones
  • • Muy básico

2000s - XML y SOAP 📄

XML-RPC (1998)

Llamadas a procedimientos remotos usando XML

Ejemplo básico: 
<methodCall>
  <methodName>getUser</methodName>
  <params>
    <param><value>123</value></param>
  </params>
</methodCall>

SOAP (2000)

Simple Object Access Protocol - muy formal y complejo

Características:
  • • XML muy verboso
  • • WSDL para describir servicios
  • • Difícil de usar

2005 - AJAX Revolution 🚀

XMLHttpRequest

Permitió peticiones asíncronas sin recargar la página

Impacto:
  • • Páginas web interactivas
  • • Single Page Applications
  • • Gmail, Google Maps

JSON (2001, popular ~2005)

JavaScript Object Notation - más simple que XML

Ventajas:
  • • Más liviano que XML
  • • Fácil de leer y escribir
  • • Nativo en JavaScript

2000-2010 - REST emerge 🌟

REST (Roy Fielding, 2000)

Representational State Transfer - una arquitectura web

Principios REST:
  • • Sin estado (stateless)
  • • URLs como recursos
  • • Verbos HTTP (GET, POST, PUT, DELETE)

Adopción gradual

Empresas como Amazon, Twitter comenzaron a usar REST

¿Por qué triunfó?
  • • Más simple que SOAP
  • • Usa HTTP estándar
  • • Fácil de cachear

2010s - Era dorada de REST APIs 💎

Explosión de APIs públicas

Twitter, Facebook, Google ofrecen APIs REST

Hitos importantes:
  • • Twitter API (2006)
  • • Facebook Graph API (2010)
  • • Instagram API (2010)

Herramientas y estándares

Aparecen herramientas para documentar y probar APIs

Herramientas populares:
  • • Swagger/OpenAPI
  • • Postman
  • • curl

2015+ - Fetch API y modernidad ⚡

Fetch API (2015)

Reemplaza XMLHttpRequest con una API moderna

Mejoras:
  • • Basado en Promises
  • • Sintaxis más limpia
  • • Mejor manejo de errores

Nuevas tendencias

GraphQL, WebSockets, gRPC complementan REST

Alternativas modernas:
  • • GraphQL (Facebook, 2015)
  • • WebSockets para tiempo real
  • • gRPC para microservicios

⚖️ Comparación de tecnologías

Tecnología Año Ventajas Desventajas Estado
CGI 1990s Simple, funcional Muy lento, limitado ❌ Obsoleto
SOAP 2000 Formal, estándar Complejo, verboso ⚠️ Legacy
XMLHttpRequest 2005 Asíncrono, compatible Sintaxis compleja ✅ Funcional
REST 2000-2010 Simple, escalable No siempre eficiente 🌟 Estándar
Fetch API 2015 Moderno, Promises No en IE 🚀 Moderno
